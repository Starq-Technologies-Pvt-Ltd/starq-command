AUTHORITY MODEL ▾
Command combines four kinds of authority — not one blanket read-only state.
SOURCERead-only projection of canonical evidence (Room, repos, build state). Command cannot write here.
RECORDCommand's own operating records — org structure, assignments, task boards. Writable where authorized.
DECISIONApprovals, holds and overrides only the Founder can make.
NOT WIREDDrawn for this design review only — no engineering is connected to it yet.
ILLUSTRATIVE DATA ▾
This screen mixes two kinds of information. Declared facts (identities, roles, reporting lines, the two in-flight engineering notes) come from what the Founder has stated directly. ILLUSTRATIVE-tagged items are example content only, to show how Command would present data once live feeds are wired — they are not observed, and no worker is shown executing a task merely because one is assigned to them. Nothing on this screen is connected to a live backend; every button is a design mock.
